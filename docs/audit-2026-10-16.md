## Validation

Local evidence and exact environment versions are in
[the M3 Pro evidence folder](https://github.com/konard/medical-neural-network-ml/tree/main/docs/case-studies/issue-1/data/m3-pro-20261016).
The small model completed requests but failed medical formatting; no accuracy
claim is made. Unit tests use mocks and small fixtures, while model/data
network tests remain explicit opt-ins. The hardware guide covers every current
workflow, distinguishes measurements from estimates, and links further work.

Validation completed locally: 611 tests passed and 43 expected model/network/layout
tests skipped; Ruff lint/format, mypy, actionlint, regular offline zizmor and
Sphinx with warnings as errors passed. The resolved macOS dependency audit
(including MLX) found no known vulnerabilities; our unpublished local package
was explicitly skipped by the advisory service. Wheel and source distribution
built successfully. A clean environment installed the wheel and ran the CLI
baseline and packaged source-manifest query without optional dependencies.

GitHub reports zero registered self-hosted runners and no releases at audit
time. The GPU workflow therefore needs a host before it can produce evidence.

The first hosted Mac compatibility run exposed a further portability bug:
`check-pipeline-status.sh` used Bash 4 associative arrays, while stock macOS
ships Bash 3.2. Local Homebrew Bash had hidden it. The status gate now uses
portable newline-delimited lists, with a regression test invoking `/bin/bash`
explicitly. Cancellation failures remain failures, and expected supersedes
retain their classification.
