# Research, migrations and reusable upstream components

Research uses upstream registries, release notes, documentation and existing issue discussions. Raw responses are preserved under `data/`; the [version tables](versions.md) distinguish registry latest from the newest version allowed by an upstream ABI/platform constraint. The supplied [dependency update practices](data/dependency-update-best-practices.md) guided the inventory, lock regeneration, native API replacements, audits and upstream reports.

## Reproduction and evidence handling

The migration experiment prints the old config warning, loads the current maintained config with FutureWarning treated as an error, demonstrates torch's CPU gap and verifies finite output from the retained fallback. `experiments/issue25_attention_bias.py` compares the native mask replacement against the former formula for query/key lengths (1,6), (3,3), (5,9). The wheel experiment performs two metadata-only resolutions. Registry scripts query authoritative PyPI/npm/GitHub data with small bounded concurrency.

Large logs are stored instead of emitted to the terminal, and log inspection uses chunks of at most 1,500 lines. Real upstream tests use a tiny text model/config with golden outputs, not the 29 GB checkpoint. Hosted CI separately tests real sample downloads, OCR, the real MedGemma CPU server and kind/Kubernetes rendering. No compatibility requirement is declared satisfied solely because an upstream report exists; local adapters and tests remain until upstream can replace them.
