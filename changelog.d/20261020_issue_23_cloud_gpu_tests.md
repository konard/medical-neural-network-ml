### Added

- Cloud GPU tests (issue #23). `python -m scripts.cloud_gpu` starts a temporary GPU machine, runs the Hugging Face model tests on it, collects the reports and deletes the machine. It has no dependencies beyond the standard library, and works the same on a laptop, in GitHub Actions and in GitLab CI. Providers are AWS, Azure and Google Cloud (Terraform modules in `infra/terraform`, VM or managed Kubernetes), a Hetzner dedicated GPU server (Robot API), a GPU host we keep (`ssh`), any Kubernetes cluster, and the local machine. Modes are `vm` (tests over SSH), `k8s` (a Kubernetes Job) and `runner` (an ephemeral GitHub Actions runner that registers with a just-in-time configuration and runs one job). Every resource carries `managed-by` and `expires-at` tags. VMs power themselves off after their time to live, and `reap` deletes whatever a failed run left behind.
- `scripts/gpu-host-run.sh` is one entry point for the GPU tests on any NVIDIA host. It checks for driver R580 or newer, installs a pinned uv and medbench, and runs `scripts/medbench-model-run.sh` under `medbench monitor`. `scripts/gpu-model-env.sh` prints the pinned settings of each model. `scripts/gpu-host-bootstrap.sh` and the Ansible playbooks in `infra/ansible` prepare a bare Ubuntu host: driver, NVIDIA Container Toolkit, k3s, and a self-hosted runner. `infra/kubernetes` holds the Job template, the NVIDIA device plugin, and Actions Runner Controller values for GPU runners. Tests keep every pin the same across the scripts, the playbooks and the case-study evidence.
- `.github/workflows/cloud-gpu-tests.yml`: pull requests lint and validate the Terraform modules, Ansible playbooks, Kubernetes manifests and shell scripts (`scripts/check-infra.sh`), and run the Kubernetes Job flow on a kind cluster. Manual runs create a GPU machine or cluster on AWS, Azure, Google Cloud or Hetzner with OIDC logins, run the tests and delete it. A daily job reaps expired resources.
- `ci/gitlab/cloud-gpu.gitlab-ci.yml` gives GitLab CI the same infrastructure checks, cloud runs and reaper. It uses GitLab's OIDC ID tokens (`ci/gitlab/cloud-login.sh`), and `after_script` deletes the machines, also after a timeout. `scripts/cloud-gpu-install-tools.sh` installs the pinned, hash-checked tools on any Debian or Ubuntu CI image.
- `docs/cloud-gpu.md` explains how to run it from a laptop, GitHub Actions or GitLab CI, which cloud settings it needs, and what is still unverified.
- Case study in `docs/case-studies/issue-23`: online research with saved evidence, every requirement with its solution plan and the existing components it builds on, and a review of the research escalation ladder.
