### Changed

- UniMedVL runtime (`scripts/unimedvl-requirements.txt`, issue #21): torch 2.8.0 → 2.14.1, torchvision 0.23.0 → 0.29.1, triton 3.4.0 → 3.8.0 and transformers 4.57.6 → 5.20.1, with every other package at its newest release, on Python 3.14 instead of 3.13. The only packages behind their newest release are the ones torch 2.14.1 or sympy pin exactly (the CUDA 13.0 libraries, cuDNN, cuSPARSELt, NCCL, NVSHMEM and mpmath); `scripts/unimedvl-requirements.in` says why. No flash-attn wheel is installed any more. flash-attn publishes wheels only for torch 2.8 and Python 3.13 or older, and that was what held the lock back. `scripts/unimedvl_server.py` now answers upstream's `flash_attn_varlen_func` import with its own function. On CUDA it uses torch's `varlen_attn`, and on other devices it uses per-sequence `scaled_dot_product_attention` with the same bottom-right causal mask. It also puts back the transformers 4.x `"default"` RoPE initialiser that upstream's Qwen2 copy looks up. On the same weights, torch 2.14.1 with transformers 5.20.1 gives the same tokens and logits as torch 2.8.0 with transformers 4.57.6 (`experiments/issue21_unimedvl_cross_stack.py`).
- A new `unimedvl-cpu` job in `model-tests.yml` installs the lock with CPU torch (`UNIMEDVL_DEVICE=cpu`). It runs upstream's `Bagel.chat` on a tiny model built from the real configs and compares the result with golden tokens and logits (`tests/test_unimedvl_upstream.py`). It also checks the attention shim against a reference implementation (`tests/test_unimedvl_attention.py`). An update of the lock that breaks upstream's code now fails on its pull request. The lock tests no longer assert exact versions.
- `pip-audit` finds no known vulnerability in the new lock, so the 14 accepted torch 2.8.0 and transformers 4.57.6 advisories are removed from `scripts/audit_dependencies.py`, and Dependency Review now allows no advisory at all.
- Dependabot's `uv` ecosystem now opens a weekly pull request for the UniMedVL lock (`directory: /scripts`) instead of leaving it out. The lock is compiled from `scripts/`, the way Dependabot compiles it, so its pull requests change only versions. `scripts/unimedvl-requirements.in` names torchvision, triton and tokenizers without a version. They are released together with torch or transformers, and Dependabot updates a group one package at a time, so exact pins on both sides would never move. The lock still pins them, and a torch or transformers update carries them along.
- llama.cpp b11707 → b11738 and its GPU build from CUDA 12.8 to CUDA 13.4. The GPU runner needs an R580 or newer driver and a Turing or newer GPU, which UniMedVL's torch 2.14.1 (CUDA 13.0) needs too.
- mlx-vlm 0.7.8 → 0.7.9. Since 0.7.9, mlx-vlm reads sampling defaults from the checkpoint only for options the caller leaves unset. `MlxBackend` sets `temperature=0.0`, so decoding stays greedy.

### Fixed

- The GPU job unpacked llama.cpp's CUDA runtime archive into a subfolder. `libggml-cuda.so` (RUNPATH `$ORIGIN`) could not find `libcudart` there, so `llama-server` would have run on the CPU. The archive is now unpacked next to the binaries, and a test checks this.
